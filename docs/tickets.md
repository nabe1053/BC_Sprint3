# 実装チケット一覧（OCTG 引合 Item List 作成エージェント 初版）

作成日: 2026-09-11 ／ 進捗の正は `.claude/memory.md` §3（本書は人が読むための説明版）

## この一覧の読み方

- **チケットは「機能グループ × 3層」で切っている。** 1グループ = 1つの画面・1つの業務の流れ。
- 3層とは:

| 層 | 何をするか（非エンジニア向けの説明） |
|----|--------------------------------|
| **BE（バックエンド）** | データベースに情報を保存・取り出す部分と、業務ルールの計算。画面からは見えない土台 |
| **API** | 画面とバックエンドをつなぐ窓口。「この住所に問い合わせると、この形の答えが返る」という取り決め |
| **FE（フロントエンド）** | 人が実際に見て操作する画面 |

- **進める順番は各グループ内で BE → API → FE**（土台から画面へ）。
  グループ自体も上から順に進める（後のグループが前のグループの土台を使うため）。
- **FUNC-02〜07 は1つのエージェントが担当する**ため、機能ごとに分けず G2 にまとめている。
- 各チケットは「実装 → 別エージェントによるレビュー → 指摘修正」で完了とする（CLAUDE.md 憲法6）。

## 全体像

| グループ | 内容 | 対応する機能 | 画面 | チケット |
|---------|------|------------|------|---------|
| G1 | 案件を作り、資料を投入する | FUNC-01, 02 | SCR-01, SCR-02 | T-101〜103 |
| G2 | エージェントが Item List 案を作る | FUNC-02〜07 | SCR-02（起動）→ SCR-03 | T-201〜204 |
| G3 | 担当者が明細を確認し訂正する | FUNC-05, 07, 08 | SCR-03, SCR-04 | T-301〜303 |
| G4 | 網羅性を照合する（抜け漏れ確認） | FUNC-03, 06, 08 | SCR-05 | T-401〜403 |
| G5 | 上司が承認し、状態を管理する | FUNC-08, 10 | SCR-06 | T-501〜503 |
| G6 | Item List を .xlsx で出力する | FUNC-09 | SCR-03 | T-601〜603 |

## G1: 案件を作り、資料を投入する

### T-101 【BE】案件・資料の保存と読取処理
- **これができるようになること**: 案件（引合の1件）と、そこに投入された PDF・Excel・メールを保存し、中身の文字を取り出せる
- **やること**: 案件・資料のテーブル操作、形式判定（PDF / .xlsx / .eml / テキスト）、テキスト抽出、読取結果（成功／読取不能／暗号化／未対応）の記録、上限超過の判定
- **完了の目安**: 4種類の資料それぞれについて「読めた・読めなかった」が正しく記録されるテストが通る。読めなかったものを成功扱いにしない
- **依存**: なし（最初のチケット）

### T-102 【API】案件・資料の窓口
- **これができるようになること**: 画面から案件を作ったり資料を投入したりできる窓口が開く
- **やること**: API #1〜#10（案件一覧・作成・詳細、資料一覧・投入・本文取得・メール構造取得・案件内検索・読取不能の記録・原資料を開く）。`/ui/*` と `/agent/*` のパス分離を守る
- **完了の目安**: 各窓口が仕様どおりの形で応答する。OpenAPI 出力 → orval 再生成 → 型チェックが通る
- **依存**: T-101

### T-103 【FE】案件一覧（SCR-01）・資料投入（SCR-02）画面
- **これができるようになること**: 人が画面から案件を作り、資料をドラッグして投入し、読取結果を目で確認できる
- **やること**: SCR-01 一覧、SCR-02 投入と読取結果表示。空・読込中・エラーの3状態を必ず用意する
- **完了の目安**: モック（mockup.html の #SCR-01 / #SCR-02）と構成・トーンが一致。読取不能の資料が一目で分かる
- **依存**: T-102

## G2: エージェントが Item List 案を作る（本プロジェクトの主役）

> このグループだけチケットが4枚。エージェント本体は BE/API/FE のどれでもない第4の部品（`backend/app/agent/`）のため。
> 実装手順は `.claude/skills/build-loop/agent-slices.md` に従う。

### T-201 【BE】成果物の保存と、完了条件の機械判定
- **これができるようになること**: エージェントが作った明細・根拠・確認事項を保存でき、「ちゃんとできているか」を機械が判定できる
- **やること**: 明細行・根拠・確認事項・原明細インベントリの保存、版（バージョン）の管理、完了条件の違反一覧を返す判定ロジック（出典が無い行・根拠の無い除外・換算値の混入 等）
- **完了の目安**: 違反の種類ごとに「見つかる／見つからない」テストが通る。換算値を1つでも通したら不合格
- **依存**: T-101

### T-202 【API】エージェント用の書き込み窓口と、実行の起動・監視窓口
- **これができるようになること**: エージェントが結果を書き込める窓口と、実行の進み具合を外から見られる窓口が開く
- **やること**: API #15〜#21（案件情報・明細・根拠・確認事項・インベントリの登録、完了条件判定、版の確定）、#12〜#14（起動・進捗取得・トレース取得）。**起動は「受け付けました(202)＋整理番号」を即返し、進捗は別途問い合わせる方式**にする（画面を待たせない）
- **完了の目安**: 起動が即座に整理番号を返し、問い合わせで進捗が取れるテストが通る。人の記録用の窓口が `/agent/*` に混ざっていない（専用テストが検出）
- **依存**: T-201

### T-203 【AGENT】エージェント本体（道具・禁止事項・実行ループ）
- **これができるようになること**: 資料を読んで Item List の案を自動で作る本体が動く
- **やること**: 設計書 `agent-plan.md` のツール一覧を1対1で実装、禁止操作を**仕組みとしてブロック**（お願いではなく強制）、実行時間の2段構えの打ち切り、全実行の記録（トレース）
- **完了の目安**: ツール単体のテストが通る。正常系シナリオを1本流し、記録を設計書と突き合わせて「設計どおりの道具だけを使い、禁止操作をせず、時間切れでなく正常終了した」ことを確認できる
- **注意**: エージェントの判断そのものはテストできないため、**シナリオ実行と記録の突き合わせで評価する**（初版は外部LLMへ送らずダミー応答で検証）
- **依存**: T-202

### T-204 【FE】実行の進捗表示
- **これができるようになること**: 「いま何をしているか」が画面で分かり、終わったら結果画面へ進める
- **やること**: SCR-02 の起動ボタン、進捗の定期的な問い合わせ表示、停止理由（正常終了／時間切れ 等）の表示、記録がある版を再実行するときの確認表示
- **完了の目安**: 実行中・完了・失敗の3状態が画面で区別できる
- **依存**: T-203

## G3: 担当者が明細を確認し訂正する

### T-301 【BE】明細の現在値と、人の記録
- **これができるようになること**: 訂正を反映した「いまの値」を出せて、誰がいつ何を直したかが残る
- **やること**: 訂正を適用した現在値の算出、訂正・取消・一致確認・確認事項の判断の記録。**記録者名は必須（AI が埋めない）**、訂正理由が空なら拒否
- **完了の目安**: 訂正 → 取消 → 現在値が元に戻る、が履歴を消さずに成立する
- **依存**: T-201

### T-302 【API】確認・訂正の窓口
- **やること**: API #23〜#26（版の要約・明細・行の根拠・確認事項）、#29〜#31, #33（訂正・取消・確認・判断の記録）
- **完了の目安**: 理由なしの訂正が正しく拒否される。orval 再生成・型チェックが通る
- **依存**: T-301

### T-303 【FE】Item List 確認（SCR-03）・根拠詳細（SCR-04）
- **これができるようになること**: 担当者が明細を1行ずつ確認し、根拠を見て、その場で直せる
- **やること**: SCR-03 の明細表と一致確認、SCR-04 の根拠ドロワーと訂正フォーム（項目選択＋新値＋理由に限定）
- **完了の目安**: 色を消しても状態が文字で分かる。塗りボタンは1画面1つ
- **依存**: T-302

## G4: 網羅性を照合する（抜け漏れ確認）

### T-401 【BE】原明細との対応関係と集計
- **これができるようになること**: 元の資料の何行目が Item List のどの行になったか、対応が取れていない行はどれか、が出せる
- **やること**: インベントリと対応関係の保存、照合集計、網羅性確認の記録
- **依存**: T-201

### T-402 【API】照合の窓口
- **やること**: API #19, #27（インベントリ登録・照合の両表と集計）、#10 と組み合わせた原資料参照
- **依存**: T-401

### T-403 【FE】網羅性照合（SCR-05）
- **これができるようになること**: 「元資料 ↔ Item List」を並べて見比べ、抜けを見つけて確認済みにできる
- **完了の目安**: 対応が取れていない行が一目で分かる
- **依存**: T-402

## G5: 上司が承認し、状態を管理する

### T-501 【BE】状態遷移・差し戻し・送付可否の記録
- **これができるようになること**: 「作成案 → 担当者確認済み → 評価確認済み」の進み方と、差し戻し、送付してよいかの判断が残る
- **やること**: 状態遷移の記録、行ごとの差し戻しコメント、差し戻し（**状態は戻さず記録として残す**）、送付可否の記録。確認者名は必須
- **完了の目安**: 未解決の確認事項が残っていても遷移できる（止めない）。差し戻しで状態が巻き戻らない
- **依存**: T-301

### T-502 【API】承認・状態の窓口
- **やること**: API #22, #28（版の履歴・人の記録一覧）、#34〜#37（状態遷移・差し戻しコメント・差し戻し・送付可否）
- **依存**: T-501

### T-503 【FE】引合書承認（SCR-06）
- **これができるようになること**: 上司が確定した表と件数を見ながら、承認・差し戻し・送付可否を記録できる
- **やること**: 確定表の常時表示、変更／判断事項・未解決事項への1操作での到達、承認・差し戻しフォーム
- **依存**: T-502

## G6: Item List を .xlsx で出力する

### T-601 【BE】5シートの .xlsx 生成
- **これができるようになること**: Item List・案件情報・根拠・確認事項・変更／確認記録の5シートを持つ Excel が作れる
- **完了の目安**: 記録が無い時点でも列見出しだけで出力できる。未解決の件数が案件情報シートに明示される
- **依存**: T-501

### T-602 【API】出力の窓口
- **やること**: API #38, #39（出力・出力履歴）、#40（版の全根拠の一括取得）
- **依存**: T-601

### T-603 【FE】出力ボタンと版の履歴（SCR-03 内）
- **これができるようになること**: 画面から Excel を出力し、過去の出力履歴を確認できる
- **依存**: T-602
